# 开发路线：完成四类事务通用闭环

更新：2026-10-09。当前能力见[STATUS](STATUS.md)，实际文件职责见[项目地图](PROJECT_MAP.md)，证据见[验收索引](evaluation/README.md)。旧 M0～M8 / P1 编号及每个旧切片的“下一建议”仅记录当时决策，不构成默认待办。

## 产品方向

当前范围由用户明确为四类事务的通用闭环，保留已有保修 AI 分析范围：建案、导入、登记/确认事实、回看/修正、本地行动、精确审批与完成证据、人工解决和历史回看。运行方式为单用户本机 Web。先完成项目，不先整理简历介绍；商业化、托管、多用户、长期真人测试和上线不作为收尾前置。打印继续暂缓。

现有闭环已经包含导入、事实修正、准备单、独立问题分析、草案保存、待办处理、人工案件解决与历史回看。不再把这些已经完成的入口拆成新任务重复开发，也不为阶段数量、Provider 数量或文件长度安排重构。

| 多轮功能累计未形成一次可追踪提交 | 后续难以区分旧基线、实际源码与已发布资产 | 2026-10-09 按新授权整理源码、提交推送并核对对应 CI；不打包或创建 Release，详见[交付记录](evaluation/source-delivery-20261009.md) |
| 门禁、响应回放、真实进程、真人与模型质量曾容易混用 | “通过”不能说明用户能独立完成或新版本可以安装 | 每份证据标明层级和未验证项，不用替身成功推导模型质量 |
| 某条服务启动曾被工具拒绝 | 单项检查结果可能被放大成整个项目不可继续 | 只保留受影响检查与明确错误；其他获授权工作正常推进，不绕过具体拒绝 |
| 尚无新观察支持搜索、OCR、连接器等扩展 | 容易继续积累小功能或通用设施，实际收益不明 | 先解决已确认可靠性问题；输入/能力扩展须有具体用户任务与失败材料 |

## 保留的代码结构

- HTTP 路由负责输入/响应，Case、Claim、Action、Approval、Timeline 等领域模块负责规则与事务，Provider 仅在模型适配器边界工作。
- Web 的 App 负责导航与跨区域协调，各 feature 负责本区展示和局部编辑状态；修复迟到结果应先统一现有身份/序号语义，不能仅因 App 较长就整体拆分。
- 当前 q1 为单 `validate`；S1 两阶段、旧七阶段和 Demo 为明确兼容分支。不为维持旧阶段补占位功能，也不为了目录名称整批迁移仍被使用的模块。
- `packages/contracts` 是已有 JSON Schema，Web 类型目前手写；`security` 空包不代表集中安全层。真实边界见地图与合同。

事实权威、来源与 Case 隔离、actor/reason/expected_version、精确审批、原件与历史保留属于产品合同，不能作为“减法”删除。

## 不预设为当前任务的能力

更多 Provider、通用聊天/SSE、多 Agent、向量检索、OCR、连接器、外部发送、通知、自动更新和原生端只在实际任务证明现有方案不足时独立评审。Ollama 历史失败保留，不自动下载、启动或作为备用重试路线。性能优化先测量，不以代码行数或架构层数推断资源问题。
