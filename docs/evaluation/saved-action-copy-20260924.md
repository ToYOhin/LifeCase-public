## 用户可见行为

已保存正文下方新增“复制已保存正文”。点击后重新读取同案待办，确认当前版本、状态、完整 payload、内容校验值、分析标识与展示记录一致，依据仍为 current，且 communication_draft 与保存的 draft_text 一致，才写入剪贴板。保留原始正文与换行，不复制未保存的处理备注。

读取失败、依据 changed/unavailable、错案、版本或正文变化均不复制；版本或依据不一致时提供“重新读取待办”，读取后需再次明确点击复制。剪贴板拒绝不会显示成功，也不回退到旧预览。初始已失效或列表未读取成功时按钮禁用。终态记录不自动等于依据失效：同案、同版本且依据仍有效时可以复制历史正文，状态不改变。

复用现有 `getActionProgress` 与 GET `/cases/{case_id}/actions/{action_id}/progress`，前后端均 no-store，读取事务实时核对分析依据。复制没有业务写接口；不确认事实，不申请或继承审批，不改变待办状态、进展或 Timeline，不表示已发送。

新组件只维护本次复制反馈和忙状态。读取返回前切案、刷新、属性变化或卸载会作废响应；双击使用同步忙锁避免重复操作。重新读取列表沿用原卡片 key，不重建编辑器。GET 与系统剪贴板不是跨进程原子事务；保证的是写入前刚读取的同案稳定快照与当前展示一致。
