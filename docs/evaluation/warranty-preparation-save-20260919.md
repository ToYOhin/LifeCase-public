## 最小持久化选择

沿用 FastAPI/React/SQLite，新增专用 `warranty_preparation_intent` 表（Case ID、当前文字、独立版本、保存时间）及 migration 17；没有新依赖。

Case goal 表示案件目标，Case.version 与生命周期历史相连，不能直接用来保存每次编辑；Claim 和 Action 分别代表事实和行动/审批。复用 Artifact 会引入文件、引用和备份一致性职责。因此采用一个专用当前值记录，不建立通用草稿、事件或工作流框架。

GET 不创建记录；PUT 在单个事务中校验 Case 类型和独立版本并保存，清空后继续保留版本，防止旧窗口恢复已清空内容。保存不改变 Case goal/版本/时间线，亦不修改 Claim/Action/审批或 actor/reason 历史。

旧数据库与支持的旧备份沿既有迁移链向前升级；旧迁移未改写，既有案件初始没有保存诉求。SQLite 完整备份保留诉求；恢复后增加对应领域读取校验。新 schema 不支持回退给旧程序直接打开。

接口与表结构详见 [API 合同](../API_CONTRACT.md#warranty-preparation-intent)、[数据模型](../DATA_MODEL.md)；使用规则见 [中文准备单](../WARRANTY_PREPARATION.md#刷新复制和保存)。
