## 实现与兼容

新问题运行 `portfolio-live-q1-<uuid>` 只执行现有证据检索/回答阶段 `validate`，正常仅一次模型适配器调用，修复/重试另计。不重新提取旧原文，避免重复候选与人工修正值冲突；没有占位步骤或伪造成功 checkpoint。

没有 question 的兼容 API 仍使用 S1 `extract → validate`；旧七阶段 Run 保留原顺序与恢复语义，明确说明没有独立问题/依据快照，不能判断其是否与当前事实一致。Fake Demo 保持原用途。预算、超时、取消、引用校验、Case 隔离及领域事实/审批权威继续复用。

原存储只有阶段输入哈希，不能在重启后还原用户问题及授权的修正事实，因此增加 migration 18：仅为 `agent_run` 添加可空的 `input_binding_json` / `input_binding_sha256`。旧行保持 NULL，不回填。绑定最多 100,000 UTF-8 字节，保存原问题、检索式、当前事实及引用摘录、材料/分段身份与哈希；不复制整份材料，不保存 Provider 响应或凭据。备份/恢复验证同一绑定合同，允许合法过期历史。没有新增表、依赖或通用工作流/多版本框架。

q1 的 execute/retry/cancel/recover 必须提交页面显示的 `expected_run_id`；缺失/不匹配返回 `409 live_agent_run_stale`。创建事务内重查未完成运行。预留、修复与最终提交均检查绑定依据；已发生的调用在依据变化时仍结算，但不提交成功 checkpoint。
